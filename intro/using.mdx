## Mental model

```
Account
  └── Project
        ├── API keys
        ├── Channels (pub/sub topics)
        └── Queues (durable jobs)
```

| Concept | Role |
|---------|------|
| **Account** | Org/billing context in QPub Cloud |
| **Project** | Isolation boundary for traffic and keys |
| **API key** | `publicId:secret` credential for REST and Socket |
| **Channel** | Named topic string for pub/sub |
| **Queue** | Named durable job stream (REST) |
| **Alias** | Optional client identity attached to a connection or message |

## Two client types

### Socket (`QPub.Socket`)

Persistent WebSocket connection. Use for:

- Subscribing to channels
- Publishing from clients that already hold a connection
- Connection lifecycle (reconnect, ping)

### REST (`QPub.Rest`)

HTTP-only. Use for:

- Publishing from servers and cron jobs
- Batch publish to multiple channels
- Issuing JWTs / creating token requests
- Queue enqueue and workers

REST does **not** subscribe to channels.

## Typical workflows

### Real-time app

1. Create a project and API key in [QPub Cloud](/cloud/index.mdx).
2. On your server, keep the API key secret.
3. For browsers, issue a JWT or signed [token request](/core/auth/token.mdx) with limited permissions.
4. Client creates `QPub.Socket`, waits for `connected`, then `channels.get(name).subscribe(...)`.
5. Servers publish with `QPub.Rest` or another Socket client.

### Server publish only

<ExampleScope defaultGroup="REST" groups={["REST"]} languages={["javascript", "typescript", "go", "curl"]}>

<CodeExamples group="REST">

```javascript
import { QPub } from "@qpub/sdk";

const rest = new QPub.Rest({ apiKey: process.env.QPUB_API_KEY });
await rest.channels.get("notifications").publish({ text: "Hello" });
```

```typescript
import { QPub } from "@qpub/sdk";

const rest = new QPub.Rest({ apiKey: process.env.QPUB_API_KEY });
await rest.channels.get("notifications").publish({ text: "Hello" });
```

```go
rest := qpub.NewRest(qpub.WithAPIKey(os.Getenv("QPUB_API_KEY")))
_, _ = rest.Channels.Get("notifications").Publish(ctx, map[string]string{"text": "Hello"}, channel.PublishOptions{})
```

```curl
API_KEY="publicId:secret"
curl -X POST "https://rest.qpub.io/v1/channel/notifications/messages" \
  -H "Authorization: Basic $(echo -n "$API_KEY" | base64)" \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"data":{"text":"Hello"}}]}'
```

</CodeExamples>

### Background jobs

<CodeExamples group="REST">

```javascript
const rest = new QPub.Rest({ apiKey: process.env.QPUB_API_KEY });
await rest.queues.enqueue("emails", { to: "user@example.com" });

await rest.queues.runWorker("emails", async (job) => {
  return { ok: true };
});
```

```typescript
const rest = new QPub.Rest({ apiKey: process.env.QPUB_API_KEY });
await rest.queues.enqueue("emails", { to: "user@example.com" });
```

```go
_, _ = rest.Queues.Enqueue(ctx, "emails", map[string]string{"to": "user@example.com"}, protocol.EnqueueOptions{})
```

```curl
API_KEY="publicId:secret"
curl -X POST "https://rest.qpub.io/v1/queue/emails/jobs" \
  -H "Authorization: Basic $(echo -n "$API_KEY" | base64)" \
  -H "Content-Type: application/json" \
  -d '{"payload":{"to":"user@example.com"}}'
```

</CodeExamples>

</ExampleScope>
