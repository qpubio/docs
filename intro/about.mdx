## What is QPub?

QPub is a high-performance, enterprise-grade real-time messaging platform that empowers developers to create and deliver instant digital experiences. By leveraging QPub's robust APIs and SDKs, developers can build applications that communicate in real-time without worrying about the complexities of scaling, latency, data integrity, and network outages.

At its core, QPub is a cloud-based publish/subscribe platform-as-a-service (PaaS) that ensures messages published by any device are received instantaneously by any number of subscribing devices with millisecond latency.

## About the QPub APIs

When building applications with QPub, there are multiple integration approaches available. However, using QPub SDKs is the recommended choice as they provide a comprehensive set of features with consistent, user-friendly APIs that work seamlessly across various platforms.

### Connection Protocols

**WebSocket Protocol (Recommended)**

- Bi-directional communication channel with persistent, single-socket connection
- Optimal for real-time applications requiring low latency
- Most QPub SDKs utilize WebSockets for establishing real-time connections
- Supports automatic reconnection and connection state management

**REST API**

- Used for authentication, configuration, and management operations
- Simple HTTP requests for non-real-time operations
- Perfect for administrative tasks and integration with existing systems

In summary, QPub SDKs and the WebSocket protocol are the go-to tools for building real-time applications with QPub, providing developers with a powerful and efficient way to create seamless and reliable connections.

## Pub/Sub Channels

Channels are the fundamental components of QPub's pub/sub model. They serve as organized message topics or categories, allowing publishers to send messages to specific channels while subscribers receive only messages from channels they're subscribed to.

### Channel Features

- **Project Isolation**: Channels are scoped to specific projects for security
- **Wildcard Support**: Subscribe to multiple channels using pattern matching
- **Presence Tracking**: Monitor who's connected to channels
- **Message History**: Optional message persistence and retrieval
- **Rate Limiting**: Per-channel rate limiting and quota management

### Supported Message Patterns

**One-to-Many (Fan-out)**
Multiple subscribers receive the same message from a single publisher. Perfect for:

- Game updates to sports fans
- Public transport times and status updates
- Live news and alerts broadcasting
- Real-time dashboard updates

**Many-to-One**
Multiple publishers send messages to a single subscriber. Ideal for:

- IoT sensor data collection
- Multi-location monitoring systems
- Centralized logging and analytics
- Vehicle tracking systems

**Many-to-Many**
Variable numbers of publishers and subscribers. Commonly used for:

- Chat applications (direct messaging and group chats)
- Collaborative editing tools
- Multiplayer gaming
- Real-time collaboration platforms
