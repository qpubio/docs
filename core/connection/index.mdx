title: "Connection"
description: "WebSocket connections for real-time QPub clients."
---

A **connection** is a WebSocket session to `wss://socket.qpub.io/v1`. Only the Socket client maintains one. The REST client is request/response and has no persistent connection.

## Creating a connection

<ExampleScope defaultGroup="Socket" groups={["Socket"]} languages={["javascript", "typescript", "react", "go"]}>

<CodeExamples group="Socket">

```javascript
import { QPub } from "@qpub/sdk";

const socket = new QPub.Socket({
  apiKey: process.env.QPUB_API_KEY,
  // autoConnect: true (default)
});
```

```typescript
import { QPub } from "@qpub/sdk";

const socket = new QPub.Socket({
  apiKey: process.env.QPUB_API_KEY,
});
```

```react
import { SocketProvider } from "@qpub/sdk/react";

<SocketProvider options={{ apiKey: process.env.QPUB_API_KEY }}>
  {children}
</SocketProvider>
```

```go
import (
	"os"

	"github.com/qpubio/qpub-go"
)

socket := qpub.NewSocket(qpub.WithAPIKey(os.Getenv("QPUB_API_KEY")))
defer socket.Reset()
```

</CodeExamples>

</ExampleScope>

Auth runs before the socket opens when `autoAuthenticate` is enabled (default).

## What you get

After connect, the SDK emits `connected` with connection metadata (including `connectionId`). You can then subscribe to channels and publish.
