---
title: "Permissions"
description: "Channel and queue permission maps for API keys and tokens."
---

Permissions decide which actions a credential may perform on which resources (usually channel or queue names).

## Shape

A permission is a JSON object: **resource key → list of actions**.

```json
{
  "notifications": ["subscribe"],
  "chat.lobby": ["subscribe", "publish"],
  "*": ["subscribe"]
}
```

| Action | Meaning |
|--------|---------|
| `publish` | Publish to a channel (also allows enqueue when `enqueue` is absent) |
| `subscribe` | Subscribe to a channel (also allows dequeue when `dequeue` is absent). Does **not** grant platform channels `_stats` / `_logs`. |
| `enqueue` | Enqueue jobs on a queue resource (`queue:<name>`) |
| `dequeue` | Pull/ack/nack jobs on a queue resource (`queue:<name>`) |
| `stats` | Subscribe to the platform [`_stats`](/core/pubsub/platform-channels.mdx) channel (usage metrics) |
| `logs` | Subscribe to the platform [`_logs`](/core/pubsub/platform-channels.mdx) channel (event log) |
| `*` | All actions on that resource |

## Matching

Permission checks match:

1. The exact resource string (channel or queue name), or
2. The resource key `"*"` (all resources)

Queue permissions use the `queue:` prefix — for example `"queue:emails": ["enqueue"]` grants access to the `emails` queue. Channel names are matched directly (`"notifications"` for a channel named `notifications`).

Use exact names or `"*"` in production credentials.

## Where permissions are set

1. **API key** — configured in [QPub Cloud](/cloud/api-keys.mdx) when the key is created/updated.
2. **JWT / token request** — optional narrower scope when issuing a token:

<ExampleScope defaultGroup="REST" groups={["REST"]} languages={["javascript", "typescript", "go", "curl"]}>

<CodeExamples group="REST">

```javascript
await rest.auth.issueToken({
  permission: {
    "user-42.inbox": ["subscribe"],
  },
});
```

```typescript
await rest.auth.issueToken({
  permission: {
    "user-42.inbox": ["subscribe"],
  },
});
```

```go
_, err := rest.Auth.IssueToken(ctx, qpub.TokenOptions{
	Permission: qpub.Permission{"user-42.inbox": {"subscribe"}},
})
```

```curl
API_KEY="publicId:secret"
curl -X POST "https://rest.qpub.io/v1/key/<keyID>/token/issue" \
  -H "Authorization: Basic $(echo -n "$API_KEY" | base64)" \
  -H "Content-Type: application/json" \
  -d '{"permission":{"user-42.inbox":["subscribe"]}}'
```

</CodeExamples>

</ExampleScope>

If a token omits `permission`, the API key’s permissions apply (subject to platform rules).

## Examples

**Read-only notifications client**

```json
{ "notifications": ["subscribe"] }
```

**Server that can publish anywhere and enqueue on `emails`**

```json
{
  "*": ["publish"],
  "queue:emails": ["enqueue"]
}
```

Denied publish returns HTTP `403` on REST, or a protocol error on WebSocket.
