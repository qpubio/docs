title: "Authentication"
description: "How clients authenticate to QPub REST and WebSocket APIs."
---

QPub messaging APIs authenticate **applications**, not end-user dashboard logins.

## Methods

| Method | Best for | Credential |
|--------|----------|------------|
| [API key](/docs/core/auth/api-key) | Trusted servers | `publicId:secret` via Basic or `api_key` |
| [JWT token](/docs/core/auth/token) | Browsers and untrusted clients | `Bearer` / `access_token` |
| [Token request](/docs/core/auth/token#token-request) | Browsers without exposing the secret | Signed payload → JWT |

Dashboard login (email/password, OAuth) is separate — see [Accounts](/docs/dashboard/accounts).

## Recommended patterns

**Server-to-server**

```javascript
const rest = new QPub.Rest({ apiKey: process.env.QPUB_API_KEY });
```

**Browser / mobile**

1. Your backend holds the API key.
2. Backend creates a JWT (`issueToken`) or a signed token request (`createTokenRequest`).
3. Client uses the JWT or `tokenRequest` / `authUrl` with `QPub.Socket`.

Never ship the API key **secret** in public client code.

## SDK options

```javascript
new QPub.Socket({
  apiKey: "...",           // or
  authUrl: "https://...",  // POST returns { token } or { tokenRequest }
  tokenRequest: { /* ... */ },
  alias: "user-42",        // optional
});
```
