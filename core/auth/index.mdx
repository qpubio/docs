---
title: "Authentication"
description: "How clients authenticate to QPub REST and WebSocket APIs."
---

QPub messaging APIs authenticate **applications**, not end-user Cloud logins.

## Methods

| Method | Best for | Credential |
|--------|----------|------------|
| [API key](/core/auth/api-key.mdx) | Trusted servers | `publicId:secret` via Basic or `api_key` |
| [JWT token](/core/auth/token.mdx) | Browsers and untrusted clients | `Bearer` / `access_token` |
| [Token request](/core/auth/token.mdx#token-request) | Browsers without exposing the secret | Signed payload → JWT |

Cloud login (email/password, OAuth) is separate — see [Accounts](/cloud/accounts.mdx).

## Recommended patterns

<ExampleScope defaultGroup="REST" groups={["Socket", "REST"]} languages={["javascript", "typescript", "react", "go"]}>

**Server-to-server**

<When group="REST">

<CodeExamples group="REST">

```javascript
const rest = new QPub.Rest({ apiKey: process.env.QPUB_API_KEY });
```

```typescript
const rest = new QPub.Rest({ apiKey: process.env.QPUB_API_KEY });
```

```go
rest := qpub.NewRest(qpub.WithAPIKey(os.Getenv("QPUB_API_KEY")))
```

</CodeExamples>

</When>

**Browser / mobile**

1. Your backend holds the API key.
2. Backend creates a JWT (`issueToken`) or a signed token request (`createTokenRequest`).
3. Client uses the JWT or `tokenRequest` / `authUrl` with the Socket client.

Never ship the API key **secret** in public client code.

## SDK options

<When group="Socket">

<CodeExamples group="Socket">

```javascript
new QPub.Socket({
  apiKey: "...",
  authUrl: "https://...",
  tokenRequest: { /* ... */ },
  alias: "user-42",
});
```

```typescript
new QPub.Socket({
  apiKey: "...",
  authUrl: "https://...",
  tokenRequest: { /* ... */ },
  alias: "user-42",
});
```

```react
<SocketProvider options={{ tokenRequest, alias: "user-42" }}>{children}</SocketProvider>
```

```go
qpub.NewSocket(func(o *qpub.Option) {
	o.TokenRequest = &tokenRequest
	o.Alias = "user-42"
})
```

</CodeExamples>

</When>

</ExampleScope>
