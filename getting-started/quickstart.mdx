Get started with QPub in minutes using our quickstart guide. This tutorial will walk you through setting up your first real-time application with QPub, from creating an account to sending your first message.

Before we begin, you'll need a QPub account and basic knowledge of JavaScript or TypeScript. If you don't have an account yet, you can sign up for free at [qpub.com](https://qpub.com). The free plan includes everything you need to get started and experiment with QPub's features.

### Getting Your API Key

The first step is to obtain your API key, which is required for authenticating with QPub services. Here's how to get started:

1. Sign up for a QPub account at [qpub.com](https://qpub.com)
2. Navigate to your dashboard after logging in
3. Go to the API Keys section in your dashboard
4. Generate a new API key for your application
5. Copy your API key and keep it secure - you'll need it for the next steps

Your API key is your gateway to QPub services, so make sure to store it securely and never share it publicly.

### Installing the SDK

Next, you'll need to install the QPub Socket SDK. The SDK provides a simple JavaScript interface for connecting to QPub's real-time services.

```bash
npm install @qpub/socket-sdk
```

The SDK includes TypeScript definitions, so if you're using TypeScript, you'll get full type safety and autocompletion in your IDE.

### Creating Your First Connection

Now let's establish a connection to QPub. The connection process is straightforward and handles authentication automatically using your API key.

```javascript
import { QPubSocket } from '@qpub/socket-sdk';

const client = new QPubSocket({
  apiKey: 'your-api-key-here'
});

// Connect to QPub
await client.connect();
console.log('Connected to QPub successfully!');
```

Once connected, your client is ready to send and receive real-time messages. The connection includes automatic reconnection handling, so your app will stay connected even if there are temporary network issues.

### Setting Up Real-time Communication

With your connection established, you can now set up real-time communication. Let's start by subscribing to a channel to receive messages, then publish a message to see the full flow in action.

First, subscribe to a channel to receive messages:

```javascript
// Subscribe to receive messages
client.subscribe('my-channel', (message) => {
  console.log('Received message:', message);
});
```

Then publish a message to the same channel:

```javascript
// Publish a message to the channel
await client.publish('my-channel', {
  text: 'Hello, QPub!',
  timestamp: new Date().toISOString(),
  author: 'quickstart-user'
});
```

When you run this code, you'll see the message you just published appear in the console, demonstrating the real-time communication flow.

### Complete Working Example

Here's a complete example that brings everything together. This code demonstrates the full workflow from connection to message exchange:

```javascript
import { QPubSocket } from '@qpub/socket-sdk';

async function main() {
  try {
    // Initialize client
    const client = new QPubSocket({
      apiKey: 'your-api-key-here'
    });

    // Connect to QPub
    await client.connect();
    console.log('Connected to QPub!');

    // Subscribe to a demo channel
    client.subscribe('demo-channel', (message) => {
      console.log('Received:', message);
    });

    // Publish a message to the channel
    await client.publish('demo-channel', {
      text: 'Hello from my QPub app!',
      author: 'quickstart-user',
      timestamp: new Date().toISOString()
    });

    console.log('Message sent successfully!');
    
    // Keep the connection alive for a few seconds to see the message
    setTimeout(() => {
      client.disconnect();
      console.log('Disconnected from QPub');
    }, 5000);

  } catch (error) {
    console.error('Error:', error);
  }
}

main();
```

This example includes error handling and demonstrates the complete flow. When you run it, you should see the connection established, your message published, and then received back through the subscription.
